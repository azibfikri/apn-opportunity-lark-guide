APN opportunity process

1. Why Lark

AWS launched a new APN. That new APN has limits for our team. So you type the opportunity in Lark. Lark still sends it to APN. You are not keeping a second set of books — you are using a different door into the same APN.

2. What you will see

Left side of the Base is the table list. For APN, ignore Client management, Opportunity management, and funding. Those are other work.

Table What you do
APN Oppt Submission Table The only table you type into. Draft with Grid + Add Record. Send from Form (or tick Submit on a draft). Watch Sync_Status on Grid.
APN Oppt Status Table View only. AWS talking back. Check AWS_Review_Status (Approved or not) and deadlines. Do not add rows here.
Docs This process guide lives here if you forget a click.
APN AWS Invitations Sales admin only (Vietnam and Indonesia). Referral accept / reject. Account managers can treat this as extra knowledge.

Repeat: the only table you add or edit for a normal opportunity is APN Oppt Submission Table. Status is view only.

Filter and Add view are optional. Use them for your own inbox (for example Failed rows). Do not leave a messy filter on the shared Grid. Do not rename or delete the shared Grid.

4. Create (first-time opportunity)

Two ways. Form sends in one step. Grid + Add Record saves a draft until you tick Submit.

Send now — Form

  1. Open APN Oppt Submission Table.
  2. Use the Form view (Fill, not Edit).
  3. Fill required fields. Follow the format rules in section 9.
  4. Click Submit.
  5. Open Grid. Watch Sync_Status for about one minute. Pending becomes Success or Failed.

Draft — Grid + Add Record

  1. Open Submission → Grid.
  2. Click + Add Record on the Grid toolbar. Do not click + New under the table list.
  3. Fill the new row. Leave Action as Create.
  4. Leave Submit and Submit_to_AWS unticked. Leave Sync_Status empty. That is a draft — AWS has not received it.
  5. When ready, tick Submit and Submit_to_AWS. If Sync_Status does not move, set Pending. Keep Action as Create. Wait about one minute.

Until 18 September 2026, you may practise Add Record but do not tick Submit on a real customer.

If Success. AWS has the create. That is not Approved yet. Check AWS_Review_Status on the Status table after about six hours.

If Failed. Click the Opportunity ID (hover → Open inside / Side Peek). Read Sync_Message. It names the field. Fix only that field. Click Retry. Leave Action as Create. Do not click Update on a Failed create — Sync_Status will not move.

You will also get Lark Messenger: Success or Failed, with the Sync_Message. The blue button in that message opens the Base row.

5. Update (stage or requirements changed)

Use this when the opportunity moves stage (for example prospect → validation) or the client requirement changed.

  1. Do not type in the Status table.
  2. Open the row → Side Peek. Check AWS_Review_Status.
  3. If it is not Approved, stop. Update will not work. Wait until AWS approves. Also do not Update if Create is still Failed.
  4. If Approved: edit the fields on Submission Grid / Side Peek. Click Update. Leave Action as Update.
  5. Wait about one minute. Watch Sync_Status.

If Failed. Read Sync_Message. Fix that field. Click Update again. Do not click Retry on an Update.

6. Referral (sales admin)

This is compulsory for sales admin. For account managers it is extra knowledge. There is no Form. Lark already fetched the AWS invitation row.

  1. Open APN AWS Invitations.
  2. Find the row (country + engagement title). New ones show invitation status Pending.
  3. Set Decision to Accept (or Reject).
  4. Set Assignee to the account manager.
  5. Set Sync_Status to Pending. Then wait. Do not skip this step.
  6. When it lands, AWS_Opportunity_ID appears and the row shows on Submission. Status still takes about six hours.

If it Fails: same idea — read Sync_Message, fix, set Pending again.

7. Two clocks

After You wait You look at
Form Submit or Update click (not an unticked draft) About 1 minute Submission → Sync_Status
Success create About 6 hours Status → AWS_Review_Status

Success on Submission is not Approved. Do not patch AWS_Review_Status by hand.

8. Do not mix buttons

If this happened Click Leave Action as
New Form submit Failed Retry Create
Approved opportunity needs a change Update Update
Update then Failed Update again Update

Retry a Failed Create. Update an Approved Success. Never Update a Failed Create. Never flip Action to Create to retry an Update.

If Retry or Update does nothing, set Sync_Status to Pending yourself and keep the same Action. A draft stays a draft until Submit is ticked. Action = Update already sets Pending on its own.

9. Format (why rows Fail)

Wrong format is the most common Fail. Read Sync_Message and fix that field.

  • Problem / customer need — at least 20 characters.
  • Phone — E.164. Example +601121555525. Plus, country code, no spaces.
  • If Stage is Launched, you must have AWS Account ID.
