## What to say, slide by slide

### 1. Title

“APN Opportunity Lark Base Submission Knowledge Transfer. Today is training. The Base goes live for all sales on **18 September**. Until then, please refrain from using it for real deals.”

### 2. Objectives

“Two things only.

One — everyone acknowledges the new process workflow. Same door, same button, same wait.

Two — I will demonstrate how to submit an AWS opportunity through Lark.

After this I will open the Base with you. Then the three processes: Create, Update, Referral.”

### 3. Open the Base — muqadimmah (speak this while they look at Lark, not the slide)

Leave Present for a moment. Paste or click:

https://g-asiapac.sg.larksuite.com/base/Xtx2b48FRabZewsZtqol0lfagOb

Then talk. Do not read every field.

**Open**

“This is the Lark Base we will all use from 18 September. Left side is the table list. For APN you only care about three tables. Ignore Client management, Opportunity management, funding — those are other work.”

**APN Oppt Submission Table** (`tbl8X591uFSYe7gj`)

“This is the table you type into.

Two views at the top.

**Form** — live send. One-shot Create. Fill, then Submit.

**Grid + Add Record** — draft. Toolbar **+ Add Record** (not **+ New** in the table list). Leave Submit and Submit_to_AWS unticked. AWS has not received it.

**Grid after send** — inbox. Watch `Sync_Status`, `Sync_Message`, `Action`, and `AWS_Opportunity_ID`. Pending becomes Success or Failed in about one minute.

If Failed, click the Opportunity ID. That opens Side Peek. Read `Sync_Message`. That sentence names the field. Fix only that. Then the button: Create Failed → **Retry**. Update Failed → **Update**.”

**APN Oppt Status Table** (`tblSeSVEhLYoZLzH`)

“This table is AWS talking back. You do not create rows here.

The field that matters is `AWS_Review_Status`. It is **not** instant. After a Success submit, come back in about **six hours**. Success on Submission is not Approved. Approved lives here.

You only **Update** an opportunity when this Status is **Approved**. If it still says pending submission, or your Create is still Failed, do not Update.”

**APN AWS Invitations** (`tblIQQ53dKKRBTe0`)

“This is Referral only. The row already exists. There is no Form. Find the invitation, Accept, assign the AM, set Pending. We will do that process on slide 6.”

**How to Filter** (click while you talk)

“On any Grid, top bar — **Filter**. Add a condition.

Examples you will actually use:

- Submission: `Sync_Status` is Failed — your error inbox.
- Submission: `Action` is Create — only first-time rows.
- Status: `AWS_Review_Status` is Approved — safe to Update.
- Invitations: `Customer_Country` is Malaysia **and** `Engagement_Title` contains the title you were given.

Filter is for this view. If you are on the shared **Grid**, do not leave a messy filter for the next person. Clear it, or save your own view.”

**How to Add a view**

“Next to the view tabs, click **+** or the view menu → **Add view** → Grid. Name it. Example: `My Failed` or your name.

You already see a personal view on Status called **Angelyn**. That is the pattern. Your view, your filter. Do not rename or delete the shared Grid. Do not add twenty views in this room — I am only showing you the button.”

**Close the tour**

“Back to the slides. I will map the three workflows first, then we walk them.”

### 4. Three workflows (say this before Create)

“So I will mention these three workflows.

One — how to create an opportunity.

Two — how to edit an opportunity in Lark.

Three is actually compulsory for **sales admin** only. But it is okay. Treat it as extra knowledge for you guys.

If you have any question, please stop me. Or just add the question in the Google Chat — or the Lark chat. I will come back to it.”

### 5. Process 1 — Create

“Two ways. **Form** sends now: Fill, not Edit, then Submit, then Grid, about one minute.

**Draft:** Grid toolbar **+ Add Record**. Leave Submit and Submit_to_AWS unticked. Practise only until 18 Sep — do not tick Submit on a real customer.

Success: AWS has it. Status table after **six hours**. Failed: Side Peek from `AWS_Opportunity_ID`. Read `Sync_Message`. Top-right **Retry**. If you click Update on a Failed Create, nothing moves.”

### 6. Process 2 — Update

“Do not Update if `AWS_Review_Status` is pending submission. Do not Update if Create is still Failed. Approved, then Grid.

Side Peek from the Opportunity ID. Edit. Top-right **Update**. Wait one minute. If that Fails, fix the field and click **Update** again. Not Retry.”

### 7. Process 3 — Referral

“APN AWS Invitations. Find with `Customer_Country` and `Engagement_Title`. Decision = Accept. Assignee = the AM. Set `Sync_Status` to Pending. `AWS_Opportunity_ID` appears when it lands. Submission shows now. Status in six hours. No Form.”

### 8. Go-live 18 September

“All sales people will use this Lark Base on **18 September**. Until then, please refrain from using this Base for live opportunities. Today is knowledge transfer. Do not create a real customer row after we leave this room.”

### 9. Tips

“Low fail means correct format before you click.

One — problem or customer need, **at least 20 characters**.

Two — phone **E.164**. Example `+601121555525`. Plus, country, no spaces.

Three — if Stage is **Launched**, you must have **AWS Account ID**.

Wrong format = Failed. Read `Sync_Message`. Fix that field. Right button.”

### 10. Help

“Error, bug, or you do not understand `Sync_Message` — do not sit on it. Ask in **APN TroubleShoot**.

Always three things:

1. Your Oppt ID  
2. Your Status  
3. Your Sync_Message  

If the question is about the APN flow itself — which door, when to wait — ask **Eylia**, `+6016-4244515`. Do not patch `AWS_Review_Status` by hand.”
